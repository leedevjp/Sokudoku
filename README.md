# Sokudoku

日本語の単語を見て、意味と読みをすばやく思い出すためのトレーニングゲームです。

公開サイト: https://sokudoku-jp.vercel.app

## マイ単語帳（P）

ホームの「出題範囲」横から個人単語の管理画面 `/personal` を開けます。表記・読み・韓国語の意味・韓国漢字音で検索し、20件ずつ表示します。単語の追加、詳細表示、編集、削除に対応し、KR/JP・ライト/ダークを切り替えられます。

APIはログインを検証し、DBのRLSでも本人の行だけを許可します。編集は同じIDを保ち、回答履歴とFSRS状態を引き継ぎます。削除は物理削除で、問題または選択した答えとして関連する回答と、その単語のFSRS状態も外部キーのCASCADEで同時に削除します。復元できません。同じ単語を再登録した場合は新しいIDで学習を始めます。別タブとの更新競合は `updated_at` で検出します。

入力はNFKC正規化と項目ごとの許可文字・長さ検証をクライアントとAPIで共有し、DBにも制約を設けます。HTML・不可視の制御文字は受け付けず、表示はReactのテキストとして行います。SQL文字列の連結や動的SQLは使いません。書き込みAPIは同一オリジン・JSON形式・受信中の32KB上限を検証します。削除後に別タブやオフラインキューから届く回答は、保存済みと区別した `discarded_ids` で破棄を通知し、キュー全体が詰まるのを防ぎます。

画面は `components/personal/`、入力検証・共通処理は `lib/personal/`、APIは `app/api/personal/` に分離しています。

## コードの構成

画面、ゲームのルール、描画、データの取得・保存を分離しています。`app/`はページとAPIの入口です。ホームのUIは`components/`、ゲームの処理は`lib/game/`に置きます。

```text
app/
  page.tsx                  ホームの入口
  game/game-host.tsx        ReactとPhaserの接続・生成・破棄
  api/game/                認証済みの単語取得・回答保存API
components/
  home/                    ホーム、出題範囲、説明、ダイアログ
  auth/                    認証フォームと認証状態・操作のフック
  notebook/                まちがいノートの一覧・単語詳細
  ui/modal.tsx             ホームとノートで共有するダイアログ
lib/game/
  types.ts                 単語・問題・回答の共通型
  rules.ts                 制限時間・演出時間・入力の二重確定防止
  selection.ts             1〜5・Pと内部難易度の対応
  question.ts              固定された問題の選択肢生成・重複回避
  session.ts               1プレイのライフ・正答数・回答・統計更新
  preferences.ts           言語・テーマ・配色
  data/
    bootstrap.ts           単語・統計の取得とオフライン復元
    database.ts            IndexedDBの接続・タイムアウト
    word-cache.ts          単語の差分マージ・同期時刻の保存
    answer-journal.ts      プレイ中の回答保持・保存処理の調整
    answer-queue.ts        未送信回答の永続化・送信・受領確認
  learning/
    engine.ts              FSRSカードの更新・学習状態の管理
    ability.ts             FSRSとは独立したユーザー能力の推定
    exploration.ts         探索の難易度・かなカテゴリの確率配分
    review.ts              復習候補の絞り込みと重みの計算
    planner.ts             重み付き抽選・セット構成・交互出題
    server.ts              サーバーでの履歴再生・状態同期
    types.ts               保存状態・学習イベントの契約
  phaser/
    create-training.ts     高密度キャンバスの生成・リサイズ・破棄
    scene.ts               入力、タイマー、状態遷移の制御
    board.ts               問題・選択肢・ライフ・時間バーの描画
    overlays.ts            ポーズ・設定・結果の描画
    effects.ts             衝突時の破片演出
    types.ts               ReactとPhaser間のコールバック契約
```

開始時は`GameHost → GameDataLoader → API / IndexedDB`で単語を準備し、Phaserを動的に読み込みます。プレイ中は`TrainingScene → TrainingSession`で回答を確定し、描画を更新します。回答はコールバックで`AnswerJournal`へ渡し、IndexedDBに保存してからAPIへ同期します。描画側から直接APIを呼びません。

変更箇所の目安:

| 変更したい内容 | 主なファイル |
| --- | --- |
| ハート数・制限時間・50msの飛行・1.5秒の正答表示 | `lib/game/rules.ts` |
| 探索・復習の確率とセット構成 | `lib/game/learning/exploration.ts`、`review.ts`、`planner.ts` |
| ユーザーの実力推定 | `lib/game/learning/ability.ts` |
| FSRSの設定・正誤評価・記憶状態 | `lib/game/learning/engine.ts` |
| 重複する選択肢の回避 | `lib/game/question.ts` |
| 問題カード・選択肢の配置と色 | `lib/game/phaser/board.ts`、`lib/game/preferences.ts` |
| 一時停止・再開・次の問題への移行 | `lib/game/phaser/scene.ts` |
| キャッシュ・未送信回答の再送 | `lib/game/data/` |
| ホームとログイン画面 | `components/home/`、`components/auth/` |
| DBスキーマ・RLS・統計SQL | `supabase/migrations/` |

ブラウザー側のキャッシュは表示・練習の継続に使用します。ユーザーの検証とデータアクセス制御は引き続きAPIとDBが担当します。ゲームの進行状態は`arming → play → flight / feedback → arming`で遷移し、`paused`から元の状態へ復帰、ライフがなくなると`end`へ進みます。

```sh

```

```sh

```

`.env.local`と`.vercel/`はGit管理対象外です。秘密キーやservice_roleキーをリポジトリや`NEXT_PUBLIC_`変数に含めないでください。Todoとは別のSupabaseプロジェクトを使用します。

## 認証設定

SupabaseのAuthentication → URL Configurationで次の値を設定します。

- Site URL: `https://sokudoku-jp.vercel.app`
- Redirect URLs: `https://sokudoku-jp.vercel.app/auth/callback`
- ローカル開発用: `http://localhost:3000/auth/callback`（ポートを変更する場合はそのURLも登録）

メールプロバイダーとメール認証を有効にしてください。PKCEコードをセッションに交換するため、確認メールは登録時と同じブラウザーで開きます。無効なリンクは`/auth/error`に案内します。

メール認証と自動ログインのセッション作成は別の段階です。認証リンクを別のブラウザーで開くと、PKCEの検証情報がなく自動ログインに失敗する場合があります。`/auth/error`からログイン画面を開き、登録済みのメールアドレスとパスワードで再開できます。認証完了をURLだけから推測して表示しません。コールバックは固定の診断区分だけをサーバーログに記録し、コード・トークン・メールアドレスは記録しません。

`/api/auth/user`はサーバーの`getUser()`で検証したユーザーのIDとメールアドレスだけを返します。未認証時は401を返し、認証関連の応答は`private, no-store`に設定します。

## データベースの管理


Prismaは使わず、`supabase/migrations/`のSQLをスキーマの正本としてGitで管理します。適用済みのファイルは編集せず、変更ごとに新しいマイグレーションを追加します。リモートの適用履歴とファイル名のバージョンを一致させます。GitへのpushやVercelのビルドだけではDBのSQLは適用されません。

現在のテーブルは`word`、`personal_word`、`answer_log`、`word_learning_state`、`learner_state`です。直近20回の統計VIEW `word_recent_stat`も作成済みです。回答の一括保存APIも実装済みです。型は`lib/supabase/database.types.ts`に保存し、DB変更時に再生成します。

## 基本モード

ログイン後に「トレーニングを始める」から起動します。ゲーム内の問題、選択肢、タイマー、ライフ、演出、ポーズ、結果画面はPhaserで描画します。

- 初期ライフは5。誤答・時間切れで1減少し、次の問題へ進みます。
- 制限時間は10秒から開始し、正答ごとに200ms短縮、下限は2秒です。毎問、現在の制限時間でバーを満たします。
- 選択肢は左上1・右上2・左下3・右下4。上段数字キー、テンキー、タッチ、クリックに対応します。
- タッチ・マウス・数字キーを押した瞬間に回答を確定し、50msで問題へ飛びます。正答なら問題、誤答なら選択肢が砕けます。
- 問題の描画完了後に単調時計で計測を開始。応答時間はキー・指を押すまでとし、飛行演出の時間は含めません。
- タブ非表示・フォーカス喪失で自動ポーズ。再開ボタンまたはEscapeで続けます。ポーズ中の時間は除外します。
- ロード完了やアドレスバーの伸縮による画面サイズ変更ではポーズを開きません。経過時間を保って再描画し、描画後の入力保護を経て続行します。すでにポーズ中なら、その状態を維持します。
- 開始・再挑戦・ポーズ解除後は500ms、回答入力とタイマーを止めます。この間の入力は破棄し、後から回答として処理しません。通常の問題間にはこの待ち時間を追加しません。
- ホームの「読み方」「意味」で問題タイプを複数選択できます。初期値は両方で、ブラウザーに選択を保存します。「読み方」だけなら漢字を含む単語だけ、「意味」だけなら意味問題だけを出題します。両方オフ、または出題範囲が未選択の場合は開始できません。
- 両タイプ選択時、漢字を含む単語は意味・読みを混在させ、それ以外は意味だけ出題します。意味選択肢は言語設定にかかわらず韓国語です。選択はURLでゲームに渡し、再挑戦・オフライン復元後も維持します。
- 出題は下記の探索・復習モデルを使用します。応答時間は記録しますが、FSRS評価や能力推定には使用しません。現在のセットは固定し、回答による変化は次のセットから反映します。

## データの取得と保存

### まちがいノート

ホームの開始ボタン下から開きます。`/api/notebook`はログインを検証し、`recent_mistake_word()`で本人の誤答・時間切れの単語を重複なしで最大100語取得します。共通単語と個人単語を含み、最後にまちがえた日時の降順で並べます。削除済みの単語は表示しません。その後に正答した単語も履歴として残します。

取得した100語をブラウザー内で10語ずつ表示し、ページ移動や単語詳細を開く際に追加取得しません。表記・読み・韓国語の意味を一覧表示し、長い内容は改行します。タップするとメモ・難易度・最後の誤答日時も確認できます。空のメモは省略します。閲覧専用で、復習状態を管理する新しいテーブルは作成しません。

ノートはサーバーに保存済みの回答を対象とします。通信失敗などでブラウザーのキューに残っている回答は、同期完了後にノートを開き直すと反映されます。API応答は`private, no-store`、SQL関数は`SECURITY INVOKER`と既存RLSで保護します。

### トレーニングの同期

/api/game/bootstrapはログインを検証します。新しいクライアントは `compact=1` を付けて `game_catalog_sync` RPCを使い、出題に必要な単語フィールドだけを受信します。ゲームで使わないメモ・監査日時・所有者IDと、FSRSと重複する直近20回統計は送りません。旧形式のAPIとRPCは開いたままのクライアント向けに維持します。初回だけ全共通単語を受信し、以後はIndexedDBの同期時刻以降の追加・更新・論理削除だけを取得します。削除マーカー、サーバー同期時刻、書き込みとのトランザクションロックは維持し、古いキャッシュとも互換です。個人単語はハード削除に対応するため毎回本人の一覧を置換します。

問題ごとにDBを参照しません。回答はクライアントで生成したUUID v7を付けてメモリーとIndexedDBへ非同期保存し、終了後に/api/game/answersへ最大200件ずつ送信します。サーバーでセッション、所有者、形式、時間・正誤の整合性を検証し、同一UUIDは上書きしません。確認済みのIDだけキューから削除します。通信失敗時はキューを残し、終了画面での再試行・再接続・次回起動で再送します。キューはユーザー別に分離し、ログアウトしても削除しません。

オフラインでは同じブラウザーに保存済みの単語とセッションを使って練習を継続できます。ローカルセッションをサーバー認可には使用せず、送信時にはサーバーで改めてユーザーを検証します。IndexedDB自体が利用できない場合は、その画面を閉じると未保存の回答を失う可能性があります。

開発時だけ /dev/game で保存しないプレビューを開けます。本番環境では404です。

## ビジュアルデザイン

提供されたライト・ダークのHTMLモックを基準に、配色、ドット背景、ブルーのコーナーフレーム、厚みのあるカード、ピンクのライフ、数字バッジをNext.jsとPhaserで統一しています。英数字はセルフホストのOutfitを使用します。画面サイズに合わせてゲーム内の比率を調整し、問題カードと選択肢を一つのまとまりとして配置します。

デザイン見本に含まれる手動の「次へ」操作は採用せず、50msの飛行、衝突・破壊、ライフ減少、問題の自動切り替えなどの既存ルールを維持しています。元のZIP・画像と展開した参照資料はリポジトリやデプロイに含めません。

## ゲームへの直接遷移と高密度描画

メイン画面のトレーニングボタンから、案内画面を挟まず最初の問題を開始します。言語・テーマ設定はメイン画面とゲームのポーズから変更できます。ルールの説明はゲーム読み込み中に表示し、説明のために開始を遅らせません。

PhaserのキャンバスはCSSサイズのまま拡大せず、端末のdevicePixelRatioに応じたフレームバッファで描画します。カメラでCSS座標系を維持するため、カードの配置、タッチ判定、飛行時間などのゲームルールは変わりません。テキストの内部テクスチャも同じ密度で生成します。GPU負荷を抑えるため、倍率3・長辺4096px・約840万画素を上限にします。

## モバイル中心のホーム画面

ホームはデスクトップでも最大480px幅の縦型レイアウトを使用します。紹介と単語カードのすぐ下に開始ボタンを配置し、画面高に合わせて装飾と余白を縮めます。ログアウトはヘッダーの言語切り替えの左に配置します。遊び方はゲームの読み込み中に表示し、未ログイン時の認証フォームはログインダイアログにまとめています。ダイアログ内だけを必要に応じてスクロールでき、閉じるボタン、Escape、背景クリックでホームに戻れます。

ポーズ画面は見やすい固定サイズの文字と太字ボタンを使用し、テキストテクスチャはフレームバッファより高密度で生成します。背面の問題画面は意図的に薄く表示します。

## 探索・復習とFSRS

ホームの「探索 / 復習」は記録の有無に関係なく選択・保存できます。両方選択時は探索5問と復習最大5問を交互に出題します。復習が2語なら5/2の7問、対象がなければ5/0です。候補が十分ある限りセット内の出題単語は重複しません。セットをすべて消化すると次のセットを作ります。復習のみで候補がない場合は、ライフを減らさず案内を表示します。

探索はユーザーの能力推定値を中心に正規分布状の重みを付けます。最初の20回答は選択範囲内の難易度を均等に探索し、その後も10%の一様分布を混ぜ、範囲内の全難易度に正の確率を残します。推定が不確かなほど分布を広げます。4択の偶然正答を考慮したロジスティックモデルで能力を少しずつ更新します。これはFSRSとは別のアプリ独自モデルです。

復習はバージョンを固定した `ts-fsrs@6.0.0` のFSRS-7を使います。目標保持率0.9、正答はGood、誤答・時間切れはAgainです。Hard/Easyの自動判定は行いません。最後に失敗した単語と復習期限が来た単語から、忘却可能性・失敗・期限超過に応じて重み付き抽選します。正答した単語も期限が来れば再び候補になります。

`word_learning_state` はユーザー×共通/個人単語×問題タイプの記憶状態を保存します。未学習の行は作りません。FSRS-7のstabilityFastを含むカードをJSONで保存し、検索用のdue_at・last_review_atとモデル版を別途持ちます。`learner_state` はユーザーごとに1行で、能力・精度・回答数・同期リビジョンを保存します。既存の最近20回VIEWとまちがいノートは維持します。

ゲーム中のFSRS・出題計算はメモリー内だけです。現在のセットは固定し、回答結果は次のセットから反映します。問題ごとのAPI呼び出しはありません。開始・再挑戦時に学習状態を取得し、ユーザー別のIndexedDBキャッシュをオフライン復元に使用します。

回答の同期時にサーバーも同じ計算を実行します。通常はlearning_processed_atが未設定の回答だけ処理し、初回・モデル更新・古いオフライン回答の到着時には履歴を時間順で再生します。リビジョン比較とトランザクションにより状態保存と処理済みマークをまとめ、重複送信や複数端末の競合を処理します。FSRSの学習に使う履歴は最近20回に制限しません。

主な実装: `lib/game/learning/engine.ts`（FSRS）、`ability.ts`（能力推定）、`exploration.ts`（探索の重み）、`review.ts`（復習候補・重み）、`planner.ts`（抽選・セット構成）、`server.ts`（初期化・同期・再計算）。同じ計算をブラウザーとサーバーで共有します。

## かなの出題範囲

出題範囲は上段「ひらがな / カタカナ」、下段「1 2 3 4 5 P」の2行です。選択は従来と同じブラウザー設定とURLに保存します。かなを選ぶと意味問題でのみ出題される旨を案内し、かなだけの範囲では「意味」が未選択なら開始できません。

wordとpersonal_wordにentry_type（word / hiragana / katakana）を追加しています。通常単語は難易度0〜10、かなは-1・has_kanji=false・hanja_reading=NULLです。かなのmeaning_koには韓国語の発音表記を保存します。選択肢は同じentry_typeだけから作り、読み問題には出しません。FSRS復習は意味問題として共有しますが、単語能力の推定とability_countには含めません。古いキャッシュにentry_typeがない場合はwordとして扱います。登録済みのかなはひらがな104件・カタカナ104件です。

## 学習状況

ホームの「学習状況」から `/dashboard` を開けます。提供されたHTML・PNGをもとに、モバイル向けの要約カード、記憶状態の構成比、最近7日の回答グラフ、段階別の学習進捗を実装しています。KR/JPとライト/ダークに対応します。

単語の意味・読みと、ひらがな・カタカナを切り替えられます。すべての指標は選択範囲に連動します。個人単語は全体の内訳と専用のP行で区別します。読みの分母には漢字を含む通常単語だけを数え、削除済み項目は除外します。DBでの時間帯検証は実際の日時変換に任せ、毎回のタイムゾーン一覧生成を避けます。総数の集計と学習済み項目の集計を分け、未学習の全単語に学習状態を結合しません。`tests/sql/read_optimization.sql` は旧集計との同値性、RLS、各種単語と時間帯、初回・差分カタログの互換性を検証し、すべてロールバックします。

`/api/dashboard` は本人確認後に `learning_dashboard(timezone)` RPCを1回呼び、集計結果だけを返します。生の回答履歴をブラウザーへ転送しません。SQLはSECURITY INVOKERと既存RLSを使用し、対象ユーザーをauth.uid()から決定します。閲覧によるFSRS更新はありません。最近7日はブラウザーのタイムゾーンで今日を含む7暦日として集計します。

記憶の表示分類は、長期安定性が7日未満・7〜21日未満・21日以上の3区分です。最後の失敗・状態未処理は最初の区分に含めます。永久的な暗記や現在の正答確率を保証する指標ではなく、画面の説明から基準を確認できます。FSRSのスケジュールと能力推定には影響しません。平均応答時間は最近7日の正答のみ、正答率の分母には時間切れも含めます。

主な実装: `components/dashboard/`（画面・チャート）、`lib/dashboard/`（型・表示集計）、`app/api/dashboard/route.ts`（認証・RPC）。デザインの原本と確認用のモックデータはGitへ含めません。
