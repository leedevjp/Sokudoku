# 개발과 검증

## 실행과 설정

README의 Node/pnpm 버전과 환경 파일 설정을 먼저 따릅니다. 환경 변수 이름은 `.env.example`이 기준이고, 실제 값과 로그인 세션은 Git에 넣지 않습니다.

Next.js 이 버전의 API/규약을 바꿀 때는 설치된 `node_modules/next/dist/docs/`의 관련 가이드를 먼저 확인합니다. 다른 버전의 관례를 그대로 적용하지 않습니다.

## 검증

| 명령/검증 | 확인하는 것 | 확인하지 않는 것 |
| --- | --- | --- |
| `pnpm typecheck` | TypeScript 계약 | 실제 DB/브라우저 동작 |
| `pnpm lint` | 코드·React 규칙 | 사용자 흐름 완료 |
| `pnpm test` | `tests/*.test.ts`의 로직/회귀 | `tests/sql`과 실제 브라우저 |
| `pnpm build` | 배포용 컴파일/페이지 생성 | 적용된 DB migration 상태 |
| `tests/sql/*.sql` | DB 제약·RLS·RPC | UI 배치 |
| 로컬 브라우저 확인 | 사용자 흐름·화면·키보드/터치 | 모의 API 사용 시 실제 DB |

2026-11-13 `8d698ea` 기준 초기 점검에서는 타입 검사는 통과했지만 테스트 178개 중 6개 실패, 린트 오류 1개/경고 2개가 있었습니다. 상세 항목은 [개선 계획](improvements.md#우선-해결할-확인된-문제)에 기록합니다. 이 숫자는 해당 기준점의 결과이며 이후 모든 커밋의 상태를 보장하지 않습니다. 후속 수정에서는 테스트 기대값과 날짜별 캐릭터 동작을 바로잡아 181개 전체 테스트가 통과했습니다. 린트 오류/경고는 별도 잔여 과제입니다.

기존 실패를 숨기기 위해 테스트를 제외하거나 단언을 느슨하게 만들지 않습니다. 현재 동작이 의도한 사양인지 먼저 확인하고 테스트와 구현 중 수정할 쪽을 결정합니다.

### 변경별 최소 확인

- **화면/문구**: 변경 파일 린트·타입, 관련 화면의 320/390/640px, 라이트/다크, 긴 단어·빈 결과·오류.
- **폼/목록**: 위 항목 + 검색/필터 후 전체 개수, 페이지 초기화, 저장 후 재조회, 수정 충돌, 삭제 취소.
- **게임**: 관련 로직 테스트 + 입력/일시정지/재개/리사이즈/종료/재시도. 답변 저장 변경은 큐·ACK·계정 분리도 확인.
- **DB/API**: 인증 실패, 입력 오류, 두 사용자 분리, 중복 전송, 관련 SQL 테스트. DB 변경과 코드 배포의 호환성을 확인.

외부 node_modules 연결을 사용하는 Windows worktree에서는 Turbopack 경로 제약이 발생할 수 있습니다. 그 환경의 대체 빌드 검증은 `pnpm exec next build --webpack`입니다. 저장소 기본 빌드 명령을 무조건 바꾸지는 않습니다.

## 작업과 전달

1. 다른 작업의 변경을 보존하고 `dev`에서 의도한 변경만 작업합니다.
2. 기능/수정 단위로 검증하고 커밋합니다. 생성물, 캡처, 로컬 도구, 단어 수입 메모는 제외합니다.
3. 요청 작업을 `dev → main` PR 하나로 정리하고, 검사 결과와 남은 문제를 적습니다.
4. 검증 후 main에 머지합니다. DB 변경이 있다면 별도 적용 결과도 남깁니다.

루트 `AGENTS.md`는 로컬 지침 포인터이며 추적하지 않습니다. 사용자 지정 로컬 지침의 경로/정책은 그 파일이 기준입니다. GitHub 변경 후 배포는 자동 흐름에 맡기고, Vercel 상태 조회를 필수 검증으로 추가하지 않습니다.

## DB 변경

- 과거 migration을 수정해 적용 완료된 DB와 기록을 어긋나게 만들지 않습니다. 새 migration을 추가합니다.
- 새 RPC는 권한, `search_path`, 소유자 필터와 RLS를 함께 검토합니다.
- `database.types.ts`는 생성 결과입니다. 스키마 변경 후 타입과 실제 RPC 계약을 맞춥니다.
- SQL 회귀 파일의 BEGIN/ROLLBACK과 테스트 사용자 생성을 먼저 읽습니다. 기본 실행 대상은 별도 검증 DB입니다. 실사용 DB에서 테스트 데이터를 만들거나 삭제하는 검증을 자동 실행하지 않습니다.
- migration 파일이 Git에 있다는 사실과 원격 적용 완료는 별개입니다.

## 문제를 좁히는 순서

| 증상 | 확인 순서 |
| --- | --- |
| 단어 목록이 비어 있음 | 검색/단계 → API 상태 코드 → 로그인/소유자 → RPC/RLS → 캐시 |
| 답변이 저장되지 않음 | 로컬 큐 → 네트워크 응답 → 사용자/ACK → 입력/삭제 참조 → 학습 revision |
| 새 화면이 예전처럼 보임 | 머지된 커밋과 로컬 변경 → 브라우저 캐시/배포 감지; 민감한 데이터 초기화부터 하지 않기 |
| 게임 멈춤/중복 입력 | scene phase → listener 정리 → pause/timer → runtime dispose |
| 느린 페이지 | 브라우저 요청 수/전송량 → API 인증/조회 수 → RPC 실행 시간; 추측으로 캐시부터 추가하지 않기 |

민감한 토큰/개인 단어 원문을 디버깅 로그에 남기지 않습니다.
