# 깨지면 안 되는 규칙 (Invariants)

> 이 문서는 기능 설명이 아니라 **리팩터링·버그 수정 때 지켜야 할 계약**이다. 구조를 단순화하더라도 아래 성질이 사라지면 안 된다.

전체 구조는 [아키텍처](./ARCHITECTURE.md), 정상 플레이는 [게임 생명주기](./GAME_LIFECYCLE.md), 실패 시 동작은 [동기화·복구](./SYNC_AND_RECOVERY.md)를 참고한다.

## 1. 답변과 학습 기록

**I-01. 답변은 한 번만 처리한다.**  
동일한 입력·정답 피드백 중복 진입·화면 갱신으로 FSRS 카드가 두 번 갱신되면 안 된다. 답변은 고유 UUID를 가진다.

**I-02. 화면에 나온 단어의 출처를 보존한다.**  
공통 단어와 개인 단어가 같은 ID를 가지거나, 표시 중 카탈로그가 바뀌어도 기록된 `source`·`selected_source`가 뒤바뀌면 안 된다.

**I-03. 다음 묶음은 이전 답변을 반영한다.**  
자동·복습·탐색 출제는 **현재 묶음이 끝난 시점**의 학습 상태로 다음 묶음을 선정한다. 이를 깨는 무조건적인 다음 묶음 선행 생성은 금지한다.

**I-04. 이미 보여준 문제는 바뀌지 않는다.**  
동기화가 도착해도 표시 중인 문제·선택지·답변 기준은 고정한다. 실제 상태 변경의 적용 시점은 다음 문제 전환이다.

## 2. 로컬 저장과 네트워크

**I-05. 로컬에 기록된 답변은 서버 장애 때문에 사라지지 않는다.**  
로컬 쓰기가 완료된 UUID는 업로드 실패·오프라인·Worker 재시작 후에도 재전송 가능해야 한다. 단, 쓰기 완료 전 강제 종료까지 보장하는 것은 아니다.

**I-06. 서버 ACK만으로는 로컬 답변을 삭제하지 않는다.**  
서버 상태·다운로드 버전 커서·ACK 대상 UUID 삭제는 원자적으로 커밋한다. 서버에 저장되었으나 로컬 커밋 전 종료되면 같은 UUID로 안전하게 재시도한다.

**I-07. 복원 시 미전송 답변을 누락하거나 중복 학습시키지 않는다.**  
스냅샷과 로컬 큐는 일관된 시점에 읽는다. 서버 FSRS 상태에 이미 반영된 답변은 재적용하지 않는다.

**I-08. 로컬 저장 성공과 서버 동기화 성공을 혼동하지 않는다.**  
종료 화면은 로컬 내구성 확인을 기준으로 한다. 서버가 오프라인이어도 유효한 로컬 캐시로 게임 진행이 가능해야 한다.

**I-09. 다른 계정의 데이터를 섞지 않는다.**  
스냅샷·전송 대기 답변·게임 프리로드는 사용자 소유자와 선택 조건을 확인한다. 계정 변경 또는 일치하지 않는 소유자는 조용히 재사용하지 않는다.

## 3. 동기화와 출제의 결합

**I-10. 단순 ACK는 문제 큐를 폐기하지 않는다.**  
서버 버전이나 관리용 revision만 달라지고 복원된 FSRS·실력 상태가 동일하다면 이미 준비된 미출제 문제를 유지한다.

**I-11. 실제 외부 변경은 다음 문제에 반영한다.**  
다른 기기의 학습 결과 또는 단어·선택지 변경이 도착하면 새 상태를 안전하게 채택한다. 새 상태 준비 도중 구버전 데이터와 신버전 답변이 섞이지 않아야 한다.

**I-12. 동기화 오류는 플레이 가능한 상태를 파괴하지 않는다.**  
버전 역행·소유자 불일치·원자적 커밋 실패는 오류로 처리하고 재시도를 허용한다. 오류를 “학습 데이터 없음”으로 취급하지 않는다.

**I-13. 공유하는 서버 카드 원본은 수정하지 않는다.**

화면의 canonical 카드와 학습 엔진이 객체를 공유할 수 있다. 답변 적용은 새 카드·행을 만들어 엔진에 넣고, 복원 기준 원본을 변경하지 않는다. 변경분은 계정과 기준 키가 일치할 때만 합친다.

**I-14. 작업 분할 중에도 답변과 갱신을 누락하지 않는다.**

복원이 화면 작업에 실행을 양보한 동안 기록된 답변도 새 엔진에 반영한다. 준비 중 도착한 실제 갱신은 다음 문제 준비 완료 전에 처리하며, 단순 ACK는 기존 큐·엔진을 유지한다.

**I-15. 저장 방식 변경이 후보 순서를 바꾸지 않는다.**

행 저장은 기존 삽입 순서를 보존한다. 성능 리팩터링이 학습 규칙을 바꾸려는 작업이 아니라면 같은 시각·난수·입력에서 출제·선택지 순서와 최종 학습 결과를 유지한다.

## 4. 이 규칙을 확인할 테스트 진입점

문서가 코드의 모든 파일을 나열하지 않도록 **행동별 테스트**만 적는다.

| 확인할 성질 | 먼저 볼 테스트 |
| --- | --- |
| 현재 문제 고정, ACK만으로 큐 유지, 다른 기기 갱신 | `tests/catalog-refresh.test.ts` |
| 강제 종료, ACK 후 재시도, 재진입 복원 | `tests/offline-restart.test.ts` |
| 증분 동기화, 버전·커밋의 일관성 | `tests/sync.test.ts`, `tests/compact-sync.test.ts` |
| 답변 저장 직후 및 동시 저장 | `tests/answer-checkpoint.test.ts` |
| 홈 첫 묶음 준비·선택 조건 일치 | `tests/home-preloader.test.ts` |
| 출제·FSRS·자동 모드 | `tests/learning-progress.test.ts`, `tests/omakase-integration.test.ts` |
| 카드·이력 행별 쓰기와 순서 보존 | `tests/learning-store.test.ts`, `tests/answer-history.test.ts` |
| 카드 변경분의 기준 키·계정, 공유 원본 불변 | `tests/prepared-learning.test.ts` |
| 변경 카드만 비교, 복원 중 도착한 답변 보존 | `tests/learning-reconcile.test.ts` |
| 작업 분할, 기존 출제 결과 보존, 다음 묶음 선행 금지 | `tests/planner-work.test.ts` |
| 서버 변경 카드 처리·revision 충돌·과거 답변 재구성 | `tests/learning-synchronizer.test.ts` |
| 결과 저장·재시도 동작 | `tests/training-lifecycle.test.ts` |

위 테스트가 모든 장애를 증명한다는 뜻은 아니다. 특히 **실제 브라우저 강제 종료, IndexedDB 저장 실패, 동기화 중 계정 전환**은 수동 또는 E2E 시나리오로도 점검해야 한다.

## 5. 변경 전 체크리스트

- [ ] 변경이 위 불변조건 중 무엇에 영향을 주는가?
- [ ] 정상 상황 외에 **업로드 중 종료 / 재진입 / 원격 변경 / 중복 이벤트**를 고려했는가?
- [ ] 이미 표시 중인 문제와 미출제 큐를 구분했는가?
- [ ] 로컬 쓰기 완료, 서버 ACK, 학습 상태 갱신을 서로 다른 사건으로 다뤘는가?
- [ ] 해당 행동을 재현하는 회귀 테스트가 있는가?

**개발 원칙:** 분기를 없애기 위해 안전장치를 제거하지 않는다. 반대로 안전장치를 설명하기 어려우면 먼저 **책임과 상태 전이의 경계**를 정리한다.
