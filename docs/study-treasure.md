# 학습 보물상자

새로 서버에 저장되는 정답·오답 5개당 상자 1개를 적립합니다. 시간 초과, 재전송 UUID, 미저장 답변, 미리보기는 적립하지 않습니다. 기존 기록은 소급 지급하지 않습니다. 탐색·복습·시험·자동 및 가나는 동일 규칙입니다. 문장 모드는 기존 답변 저장 경로와 별도이므로 포함하지 않습니다.

학습 현황에서 미개봉 상자를 검은 실루엣과 ?로 표시합니다. 가장 오래된 상자만 터치할 수 있으며 한 번에 1개를 개봉합니다. 서버가 커먼 60%, 레어 30%, 유니크 10%로 등급을 정해 저장합니다. 매 10개마다 등급 수량을 보장하는 방식이 아닙니다. 현재 보상은 상자 등급 수집이며 별도 재화나 아이템은 없습니다.

## 저장과 권한

- `answer_log` AFTER INSERT 트리거가 전용 사용자 진행 카운터를 올립니다. 삭제 가능한 답변 수를 매번 나누어 계산하지 않습니다.
- 계정별 카운터 행 잠금으로 동시 적립을 직렬화합니다. 5개 경계에서 상자 ordinal을 발급합니다.
- 개봉은 같은 카운터 행을 잠그고 소유자 및 첫 미개봉 상자인지 확인합니다. 같은 상자 ID 재요청은 저장된 결과를 반환하고 다시 추첨하지 않습니다.
- 일반 사용자는 상자/카운터를 직접 수정할 수 없습니다. RLS는 소유자 조회만 허용합니다. 개봉 RPC는 직접 쓰기 권한 없이 결과를 서버에서 결정하기 위해 의도적으로 SECURITY DEFINER를 사용하며, auth.uid/소유자/빈 search_path/함수 실행 권한을 검사합니다. Supabase advisor의 authenticated definer 경고는 이 의도된 RPC에 해당합니다.
- `GET/POST /api/treasure`는 인증·입력 UUID·Origin을 검증하고 private/no-store로 응답합니다. 클라이언트는 등급을 제출할 수 없습니다.
- 대기 상자는 처음 12개씩 보여주며 개봉 후 다음 항목을 채웁니다. 개봉 등급 수집 개수는 별도로 유지합니다.
- 기존 단어/답변 삭제는 획득한 상자를 회수하지 않습니다. 계정 삭제 시 상자도 삭제됩니다.

## 검증

`tests/sql/study_treasure.sql`: 합성 사용자/단어만 생성하고 전체 ROLLBACK. 4/5/10개 경계, 시간 초과 제외, UUID 재전송, 오답 적립, 소유자 분리, 직접 쓰기 차단, 개봉 순서, 재요청 결과 유지, 단어 삭제 후 보상 유지 검증.

브라우저: 미개봉 실루엣, 연속 터치 차단, 3등급 연출, 12개 이후 목록 보충, 새로고침 보관, 동작 줄이기 및 연출 로딩 실패 후 결과 확인을 검증합니다. 연출은 기존 마법사에 맞춘 v2 동작을 사용합니다.
